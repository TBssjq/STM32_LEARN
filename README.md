# STM32F103 外设练手工程

STM32F103C8T6（Blue Pill）上的几个常用外设驱动与演示：SSD1306 OLED、有源蜂鸣器、外部 LED、光敏传感器。
CMake + Ninja + arm-none-eabi-gcc 构建，工程骨架由 STM32CubeMX 生成（`STM32_LEARN.ioc`）。

## 构建

**必须显式指定工具链文件**，否则 CMake 会按"本机 Windows"来编译，`arm-none-eabi` 的编译探测会直接失败：

```powershell
# 工具链文件里用的是 arm-none-eabi-gcc，所以要先把 bin 目录加进 PATH
$env:Path = "D:\app\ST\STM32CubeCLT_1.22.0\GNU-tools-for-STM32\bin;D:\app\ST\STM32CubeCLT_1.22.0\Ninja\bin;$env:Path"

cmake -G Ninja -S . -B cmake-build-stm32 `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake
cmake --build cmake-build-stm32
```

也可以用预设：`cmake --preset Debug`（输出目录是 `build/Debug`）。

> 工程里有两套构建目录：`cmake-build-stm32/`（本文档使用）和 `build/Debug/`（预设）。烧录时注意别烧错，目标文件是 **`cmake-build-stm32/STM32_LEARN.elf`**。

若有旧的失败缓存，先删掉再配置：`Remove-Item -Recurse cmake-build-stm32`。

## 引脚分配

| 功能 | 引脚 | 备注 |
|---|---|---|
| 外部 LED | **PA0** | 输出高电平点亮（绿灯/蓝灯可省电阻，红灯串 1kΩ） |
| 板上 LED | PC13 | 低电平点亮，免接线 |
| 蜂鸣器 I/O | **PA6** | TIM3_CH1，低电平触发，PWM 门控调音量 |
| OLED SCL | **PB6** | I2C1_SCL |
| OLED SDA | **PB7** | I2C1_SDA |
| 光敏 AO | **PA1** | ADC1_IN1（模拟输入） |
| 光敏 DO | **PA2** | 数字输入，内部上拉 |
| 电机 A 调速 | **PB8** | TIM4_CH3，接 TB6612 的 `PWMA` |
| 电机 B 调速 | **PB9** | TIM4_CH4，接 TB6612 的 `PWMB` |
| 电机 A 方向 | **PB12 / PB13** | 接 TB6612 的 `AIN1` / `AIN2` |
| 电机 B 方向 | **PB14 / PB15** | 接 TB6612 的 `BIN1` / `BIN2` |
| 自检探针 | PB5 | 仅"接线自检"演示使用 |
| 调试口 | PA13/PA14 | SWDIO / SWCLK，下载调试用，勿占用 |

## 接线

### 第一步：在蓝板上找引脚

**一律看板子上的丝印文字**（Blue Pill 两侧都印了引脚名）。两侧顺序是固定的：

- **左列**（从 USB 接口那一端开始）：`VB, C13, C14, C15, A0, A1, A2, A3, A4, A5, A6, A7, B0, B1, B10, B11, RES, 3V3, GND, GND`
- **右列**：`3V3, GND, 5V, B9, B8, B7, B6, B5, B4, B3, A15, A12, A11, A10, A9, A8, B15, B14, B13, B12`

> **不要按"第几个脚"去数。** 板子插到面包板上之后朝向不定，从另一头数就会数错，而且接错脚非常难查。

### 第二步：逐个模块接

#### 1. 外部 LED

```
   LED 长脚(阳极) ──────────── 蓝板丝印 A0     (PA0，输出高电平点亮)
   LED 短脚(阴极) ──────────── 蓝板丝印 GND
```

绿灯 / 蓝灯 / 白灯可以直接接（GPIO 内阻约 35Ω，电流约 3~14mA）；
**红灯 / 黄灯必须串 1kΩ**，否则直连电流可达 30~45mA，超过单脚 25mA 上限。

#### 2. MH-FMD 蜂鸣器（3 针）

```
        MH-FMD                        STM32F103
   ┌────────────────┐
   │  GND  VCC  I/O │
   └───┬────┬────┬──┘
       │    │    └───────── 丝印 A6    (PA6 / TIM3_CH1)
       │    └────────────── 丝印 3V3   ← 必须 3.3V，不能接 5V
       └─────────────────── 丝印 GND
```

- 模块是**低电平触发**（I/O 拉低才响），所以 `buzzer.h` 里 `BUZZER_ACTIVE_LEVEL = 0`
- **VCC 必须接 3.3V**：若接 5V，MCU 的 3.3V 高电平不足以让模块内的 PNP 管截止，会出现"一直微响、关不断"
- 音量由 PWM 占空比控制，用 `BUZZER_SetVolume(1~100)` 调

#### 3. SSD1306 OLED（4 针）

```
      SSD1306 OLED                    STM32F103
   ┌─────────────────┐
   │ GND VDD SCK SDA │
   └──┬───┬───┬───┬──┘
      │   │   │   └──────── 丝印 B7   (PB7 / I2C1_SDA)
      │   │   └──────────── 丝印 B6   (PB6 / I2C1_SCL)
      │   └──────────────── 丝印 3V3
      └───────────────────── 丝印 GND
```

- 模块**自带上拉电阻**，不用外加
- 模块丝印上的 `SCK` 就是 I2C 的 `SCL`；模块的引脚顺序各厂不同（也有印 `GND VCC SCL SDA` 的），**以模块自己的丝印为准**
- 地址默认 0x3C，驱动会自动探测 0x3C / 0x3D；硬件 I2C 不通会自动改用软件位翻转，SDA/SCL 接反也能自动交换
- 想看实际走的是哪条通道，在初始化后调一次 `SSD1306_GetLinkStr()` 显示出来即可（返回 `HW I2C` / `SW I2C (bit-bang)` / `SW I2C SWAPPED`）

#### 4. 光敏传感器（4 针：VCC / GND / DO / AO）

```
      光敏模块                        STM32F103
   ┌─────────────────┐
   │ VCC GND DO  AO  │
   └──┬───┬──┬───┬───┘
      │   │  │   └─────── 丝印 A1   (PA1 / ADC1_IN1，模拟量)
      │   │  └─────────── 丝印 A2   (PA2，数字量，内部上拉)
      │   └────────────── 丝印 GND
      └────────────────── 丝印 3V3
```

- `AO` **必须接在带 ADC 的引脚**上。这块板引出来的 ADC 脚只有 `A0~A7`、`B0`、`B1`（`C0~C5` 没引出）；`A0` 已被 LED 占用，所以用 `A1`
- `DO` 是比较器输出，阈值由模块上的**蓝色电位器**拧；两个 LED 会跟随 DO 亮灭，方便你调阈值
- 模块 VCC 必须 3.3V（`AO`/`DO` 接的是模拟脚，不耐 5V）

#### 5. TB6612FNG 电机驱动（双路）

```
        TB6612FNG 模块                     STM32F103 / 电源
   ┌────────────────────────┐
   │  VM   VCC   GND   STBY │
   │  AIN1 AIN2 PWMA        │
   │  BIN1 BIN2 PWMB        │
   │  AO1 AO2  BO1 BO2      │
   └───┬────┬────┬────┬─────┘
       │    │    │    │
       │    │    │    └────────── 3V3     ← STBY 接高电平才使能（跳线即可）
       │    │    └─────────────── GND     ← 必须与 MCU 共地
       │    └──────────────────── 3V3     ← 逻辑电源，必须 3.3V
       └───────────────────────── 电机电源正极（2.5~13.5V）

   控制信号：
     AIN1 -> 丝印 B12      AIN2 -> 丝印 B13      PWMA -> 丝印 B8
     BIN1 -> 丝印 B14      BIN2 -> 丝印 B15      PWMB -> 丝印 B9

   输出（接电机）：
     AO1 / AO2 -> 电机 A 的两根线      BO1 / BO2 -> 电机 B 的两根线
```

- **VCC 必须 3.3V**：这样 MCU 的 3.3V 逻辑电平和它完全匹配（若 VCC 用 5V，输入高电平门限会被抬高，3.3V 可能识别不可靠）
- **GND 必须和 MCU 共地**，否则控制信号没有参考电平
- **VM 是电机电源**，与逻辑电源分开：小电机可以临时用蓝板的 `5V`，但电机启动/堵转电流会把 USB 供电拉垮导致 MCU 复位，稳妥做法是用独立电池（如 4 节 AA = 6V），并**把电池负极与蓝板 GND 接在一起**
- 电机电源两端建议并一个 **100µF 电解电容**（模块上通常已有小的，外加一个更稳）
- `STBY` 悬空/低电平时模块处于待机，电机完全不转——**这是最常见的"接好了却不转"的原因**，确认它接到了 3V3

电机驱动的 API：

```c
void MOTOR_Init(void);
void MOTOR_SetSpeed(uint8_t ch, int16_t speed);  // ch = MOTOR_A / MOTOR_B，speed = -1000~1000
void MOTOR_Stop(uint8_t ch);                     // 停止：输出高阻，自由滑行
void MOTOR_Brake(uint8_t ch);                    // 刹车：短路制动，停得干脆
void MOTOR_StopAll(void);
```

- `speed` 的**正负代表方向**（哪个方向是"正转"取决于电机两根线怎么接，接反了就对调 `AO1/AO2`，或把符号反过来用）
- PWM 固定 20kHz，高于人耳听阈，电机不会啸叫
- 想用软件控制使能，把 `motor.h` 的 `MOTOR_USE_STBY` 改成 `1`（默认 `0` = STBY 跳线到 3V3）

### 第三步：整体供电与接地（面包板）

#### 电源怎么分配

面包板的红/蓝导轨**中间是断开的**，正好用来把"逻辑电源"和"电机电源"分开，避免电机电流干扰 MCU：

```
 ┌────────────────────────── 面包板（横向看）──────────────────────────┐
 │ 红轨 [左段 3.3V]═══════════╳═══════════[右段 VM 电池+ ]              │
 │ 蓝轨 [左段 GND ]═══════════╳═══════════[右段 电机 GND ]              │
 │                      ↑                                            │
 │                 ╳ = 导轨断口（左右不通）                            │
 └───────────────────────────────────────────────────────────────────┘
        左段 = 逻辑电源（3.3V / GND）   右段 = 电机电源（VM / 电机地）
        两段蓝轨之间只用一根线连起来 —— 这是唯一的共地点（单点接地）
```

| 取电点 | 从哪取 |
|---|---|
| 蓝板 `3V3` | 一根线 → 红轨**左段** |
| 蓝板 `GND` | 一根线 → 蓝轨**左段** |
| OLED `VDD`、光敏 `VCC`、蜂鸣器 `VCC`、TB6612 `VCC`、TB6612 `STBY` | 红轨**左段**（3.3V） |
| OLED `GND`、光敏 `GND`、蜂鸣器 `GND`、LED 阴极、TB6612 逻辑侧 `GND` | 蓝轨**左段** |
| 电池 `+` | 红轨**右段** → TB6612 的 `VM` |
| 电池 `−` | 蓝轨**右段** → TB6612 靠 `VM` 的那个 `GND` |
| 两段蓝轨之间 | **一根短跳线**（共地，必须接） |

要点：

- 逻辑电源和电机电源**不要共轨**：电机电流会在导轨上产生压降和毛刺，轻则屏幕闪、重则 MCU 复位
- 但**地必须共**：两段蓝轨之间连一根线，形成"单点接地"（星形接地），信号才有共同参考
- 只想用一条轨也能跑，但电机启动时 MCU 复位概率明显升高

#### TB6612 的多个 GND 引脚

模块上有 **3 个 GND**（`VCC` 旁边一个，两侧排针末端各一个；不同批次位置略有差异，以丝印为准），**它们内部是连通的，接一个就够**：

- 至少接**靠近 `VM`/`VCC` 的那个 GND**（电机电流主要从这里回流）→ 蓝轨右段
- 剩下两个可以空着；想更稳就用短跳线把它们也并到同一条 GND 轨
- **不要把 VM 的回流地和逻辑地放在两条互不相连的轨上**，那样两边没有共同参考，控制信号会失效

#### 推荐的接线顺序

1. **先接地与逻辑电源**：蓝板 `GND` → 蓝轨左段；蓝板 `3V3` → 红轨左段
2. **接逻辑模块**：OLED / 光敏 / 蜂鸣器 / LED 的 VCC、GND 都从左段取，信号线接各自引脚
3. **接 TB6612 逻辑侧**：`VCC`、`GND`、`STBY`(→3V3)、6 根控制信号线（`AIN1/AIN2/PWMA/BIN1/BIN2/PWMB`）
4. **接电机电源**：电池 `+` → 红轨右段 → `VM`；电池 `−` → 蓝轨右段 → TB6612 近 `VM` 的 `GND`
5. **连通左右两段蓝轨**（一根线，完成共地）
6. **最后接电机**：`AO1/AO2` 接电机 A，`BO1/BO2` 接电机 B

#### 上电前检查

- 万用表蜂鸣档量 **红轨左段 ↔ 蓝轨左段**：不应导通（导通就是 3.3V 短路）
- 量 **红轨右段 ↔ 蓝轨右段**：不应导通（导通就是电机电源短路）
- 确认 `STBY` 已接 3V3
- 确认电机电源电压在 `VM` 允许的 2.5~13.5V 之内
- 第一次试转时把电机**拿在手里**，不要固定在桌面/支架上

### 面包板使用的三个坑

1. **主区只有"同一列的 5 个孔"互相连通**，相邻两列是隔离的；模块引脚插在三列里，必须各引一根线到目的地。
2. **中央隔离槽里没有触点**，3 针 / 4 针模块如果横跨着插，中间那根针会悬空——肉眼看不出来，插得再紧也没用。
3. **电源轨在中间是断开的**（左右两段不通）。若把 3V3 / GND 引到导轨，要确保所有 VCC/GND 都插在**同一段**上。

### 接线自检

如果某个模块不工作，先用"接线自检"演示（探针插 PB5，灯语见下文）确认是哪根线没通，不要靠猜。

## 代码结构

```
Core/Inc, Core/Src            CubeMX 生成：只改 USER CODE 区
  main.c                      初始化 + 一行 APP_Main()；Error_Handler 只调用 APP_ErrorTrap()

App/                          应用层（业务与演示，与 STM32 无关）
  app_main.h                  C/C++ 边界头：extern "C" 暴露 APP_Main()/APP_ErrorTrap()
  app_main.cpp                业务入口：初始化各层 + 选演示；错误陷阱
  app_demo.hpp/.cpp           app::demo::motorTest / lightSensor / buzzerMelody
  app_bomb.hpp/.cpp           app::bomb::run 定时炸弹演示

Bsp/                          板级层：本板专有（换板只改这里）
  board.hpp/.cpp              bsp::led1/led2、bsp::motorA/motorB 对象图与引脚接线
  wiretest.hpp/.cpp           bsp::wiretest 接线自检（探针法，见下）

Drv/                          驱动层：通用驱动，可跨板复用
  gpio.hpp                    drv::GpioPin + drv::gpio（时钟 / 模式 / 读写封装）
  time.hpp / irq.hpp          drv::time（毫秒 / 延时）、drv::irq（关中断）
  led.hpp/.cpp                drv::Led：一个 LED 对象（有效电平可配）
  motor.hpp/.cpp              drv::Motor：TB6612 单路（TIM4 通道 + 方向）
  buzzer.hpp/.cpp             drv::buzzer：MH-FMD，有源/无源可切、音量(占空比)可调
  light.hpp/.cpp              drv::light：寄存器直接配 ADC1 + DO 数字输入
  bsp_oled.c/h, bsp_oledfont.h  SSD1306 驱动保留为 C：1KB 显存、硬件/软件 I2C 自动兜底

Legacy/                       历史代码，不参与编译（旧版 OLED 驱动 + BMP 图）
```

约定：依赖方向单向向下 **`App → Bsp → Drv → HAL`**。`main.c` 只管初始化和调用 `APP_Main()`；新功能写进对应层，不要堆进 main.c；App 层不直接调用 HAL/寄存器。

驱动都不依赖 CubeMX 重新生成：TIM4、ADC1 等外设由驱动内部用寄存器直接配置。

## 接线自检（探针法）

找一根杜邦线，一头插 **PB5**，另一头当探针去碰要检查的点，看 LED 灯语：

| LED | 含义 |
|---|---|
| 常亮 | 该点接在 3V3 上 |
| 慢闪 1Hz | 该点接在 GND 上 |
| 急快闪 8Hz | **悬空 / 开路 —— 就是这根线没接通** |
| 完全不亮 | 固件没跑起来 |

先拿"探针悬空 / 碰蓝板 GND / 碰蓝板 3V3"自检一遍，确认探测器本身是好的。

## 注意事项

1. **蜂鸣器是低电平触发（PNP 管），VCC 必须接 3.3V。** 若接 5V，MCU 的 3.3V 高电平不足以让它截止，会一直微响、关不断。
2. **OLED 驱动会自动兜底**：自动探测地址 0x3C / 0x3D；硬件 I2C 不通时自动改用软件位翻转；SDA/SCL 接反也能自动交换。屏幕第 2 行会显示实际走的通道（`HW I2C` / `SW I2C (bit-bang)` / `SW I2C SWAPPED`）。
3. **OLED 全屏刷新在 100kHz I2C 下约 100ms**，需要跟随快速事件的画面请用 `SSD1306_RefreshArea()` 局部刷新（例如"定时炸弹"的节拍指示）。
4. **模拟脚（PA0~PA7、PB0/PB1）不耐 5V**，外接模块请一律用 3.3V 供电。
5. **电机必须单独考虑供电**：电机启动电流大，从 USB 取电容易把电压拉垮导致 MCU 复位。用独立电池给 `VM`，并且负极与蓝板 GND 连在一起。
6. 开发过程中踩过的坑、错误归因与自检清单见 [`MISTAKES.md`](MISTAKES.md)（20 条 + 23 条清单），改动驱动前建议翻一下。
